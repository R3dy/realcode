## Comments

### 2-C1 — build.yaml deletion breaks two tests that §10 swears "run unchanged"
**Plan section:** §9 (A17.1 build.yaml criterion), §10 (Regression), §8
**Problem:** The deletion criterion added for 1-C3 is correct, but its blast radius is understated. Two test files in the plan's own "run unchanged" regression list physically load `agent-specs/build.yaml`:
1. `tests/agents.test.ts:71-80` — "loads and validates all 6 agent specs" iterates `["frame", "discover", "plan", "spec", "build", "ship"]` and calls `loadAgentSpec(path.resolve(REPO_ROOT, \`agent-specs/${stage}.yaml\`))` on each. After deletion, the `"build"` iteration throws (file not found) → the test fails.
2. `tests/engine/stage-graph-xor.test.ts:35` — `const BUILD_SPEC = path.resolve(REPO_ROOT, "agent-specs/build.yaml")`, used as `worker_spec`/`validator_spec` in `innerLoopStage()` (lines 78-79). `validateGraph` `fs.existsSync`-checks those paths when a stage has the inner_loop triad and no `agent_spec` (`src/engine/stage-graph.ts:138-148`), so "accepts a stage with the inner_loop triad (no agent_spec) — the A4.4 pattern" (test line 149-156) throws `GraphValidationError` → the test fails. (Checked the siblings: the "rejects both agent_spec AND triad" test at line 106 survives — its XOR message is collected at stage-graph.ts:132-134 while the existsSync branch at 138 is guarded by `!hasAgentSpec` and its `agent_spec` is FRAME_SPEC, which exists; `tests/engine/build-loop.test.ts:29-30`, `dispatcher-guard.test.ts:41-42,101`, and `lease-heartbeat.test.ts:29-30` only use the `agent-specs/build.yaml` string in post-validation in-memory graph mutations with mocked runners, so it never hits disk — they're genuinely unchanged. Only the two tests above break.)
**Required change:** Extend A17.1 with two criteria: (a) `tests/agents.test.ts` "all 6 agent specs" loop updated to the 5 remaining stage specs (its assertions are shape checks; the build entry is the only build.yaml dependency); (b) `tests/engine/stage-graph-xor.test.ts` `BUILD_SPEC` fixture repointed at an extant spec (e.g. `agent-specs/worker.yaml` — it is only used as a path-that-exists placeholder). Then fix §10's Regression list: mark these two files as **updated by this story**, not "run unchanged," and keep the "run unchanged" claim for build-loop / dispatcher-guard / lease-heartbeat only.

### 2-C2 — A17.1's criteria permit a self-contradictory plan.yaml (leftover prohibition at line 12) and a traversal guard that bans the path it instructs
**Plan section:** §4.2 (example prompt), §9 (A17.1 criteria 1, 3, 4)
**Problem:** Two self-contradiction vectors survive the criteria as written — the same defect class as round 1's 1-C2:
1. **plan.yaml:12 is outside every deletion scope and every grep.** The file says (lines 10-12): "Work ONLY from the prior artifacts provided in the prompt below. Do NOT read or explore the workspace source tree — all the context you need is in the prompt. **Do NOT search for or read any external files (phase guides, templates, etc.).**" Criterion 1 requires deleting the inlined format blocks at "current lines 14-42" and adding the read-from-cache-path instruction — it does not touch line 12, and neither grep criterion catches the phrase ("Do NOT search for or read any external files" matches neither "## … format" nor "Do NOT read or search for any anymake docs"). A worker executing the criteria mechanically produces a plan.yaml that instructs "Read anymake's Phase 2 guide and templates…" and, three lines later, forbids reading phase guides and templates.
2. **The traversal guard bans the cache path's `node_modules` segment.** §4.2's example adds "Context discipline: Do NOT traverse node_modules/, data/, .git/, dist/, .next/, coverage/" to a prompt that simultaneously instructs reads under `/root/.cache/opencode/packages/anymake@git+https:/github.com/R3dy/Anymake.git/**node_modules**/anymake/…`. Criteria 1, 3, and 4 say "traversal guard kept / added if not present" — a faithful transcription of the current guard wording re-introduces the tension in every rewritten pipeline-stage spec. (Empirically agents have read the cache path despite blanket prohibitions — that's how 1-C1's evidence exists — but the spec text should not rely on agents disobeying a guardrail.)
**Required change:** (a) Extend criterion 1 to remove plan.yaml's external-files prohibition along with the inlined blocks — i.e. the deletion scope covers current lines 10-12, keeping at most the workspace-source-tree discipline ("Do NOT read or explore the workspace source tree"), which does not conflict with reads outside the workspace. (b) Add a grep criterion: `Grep for "Do NOT search for or read any external files" in agent-specs/ returns empty.` (c) Word the traversal guard in §4.2's example and in the criteria with an explicit carve-out — e.g. "Do NOT traverse `node_modules/`, `data/`, `.git/`, `dist/`, `.next/`, `coverage/` **in the workspace** (the anymake cache path above is exempt — read those files directly; the guard bans wandering large trees, not reading named files)."

## Verdict

**VERDICT: NEEDS CHANGES** — comments 2-C1…2-C2 must be resolved; architect revises and resubmits for round 3.

**Summary:** All four round-1 comments are genuinely addressed — the mechanism pivot to direct cache-path reads is fully verified against the container logs (58/58 completed reads, zero errors), the smoke proof makes it enforceable, the allowlist/ship resolution is exactly the sanctioned either/or, and the regression list now names the right files. But the revision introduced two narrow, mechanical defects the criteria don't catch: the build.yaml deletion silently breaks `tests/agents.test.ts` and `tests/engine/stage-graph-xor.test.ts` (both listed as "run unchanged"), and A17.1's deletion scope stops one line short of plan.yaml's external-files prohibition while the reused traversal-guard wording bans the very `node_modules` segment the new primary path passes through. Both fixes are criterion-level edits; no design re-opening needed. Non-blocking nits for the same round: §3's module list still omits `agent-specs/build.yaml` (round 1's 1-C3 asked for it there too), §3's Integrations row still says "Skill tool in headless opencode (already available)" — contradicting §2 bullet 6's "unproven"; and per round 1's dimension-4 note, ADR-012 may cite INV-7's existing `change.yaml` skill-delegation precedent rather than presenting delegation as new.
